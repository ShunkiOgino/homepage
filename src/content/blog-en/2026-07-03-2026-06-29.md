By inserting a demo flag (OGINO_DEMO=1) at external API connection points, I reproduce authentic routing behavior with zero real data. This approach reduces both the cost of re-recording videos and the operational risk of exposing a live environment to zero, delivering only the tactile experience.

When communicating the value of a tool, I initially tried to either carefully create screen recordings or simply make the live environment public. However, I realized that the former comes with high correction costs and the latter carries the risk of backend operational overhead.

For example, when releasing a self-made manga panel editor, I implemented it as a "hands-on demo" rather than using still images or videos. The original tool depended on a server-side API, but by extracting the client-side JS logic and replacing the API portions with stubs (static data), I ported it to a self-contained HTML file that requires no backend. This made it possible to provide the core experience—arranging panels and editing text—directly via an iframe.

Additionally, to maintain the "persuasiveness of authenticity," I use a strategy where I keep the actual backend but control only the appearance. By inserting a demo flag (OGINO_DEMO=1) at external API connection points, I implemented it so that deterministic dummy data is returned only for specific prompts. This safely reproduces the behavior where data of the correct format is rendered via actual routing.

Regarding demo video production, I built a pipeline using Playwright to control transitions, clicks, and subtitle overlays via JSON-formatted scripts, eliminating the cost of manual recording. For areas where selector specification was difficult, I resolved it with XY coordinate clicks to ensure reproducibility.

What is indispensable in this kind of design is the perspective of "how the recipient perceives it" rather than the "systemic correctness." To the user, it looks like rendering that passed through actual routing, but in reality, it is a state of zero real data controlled by a single flag—designing visual and psychological conviction, more than functional correctness, is essential for intuitive communication.

Where should the cost of communicating value be allocated? Instead of pursuing implementation complexity, I allocate resources to increase the resolution of the experience. By optimizing that balance, the way a message is received changes dramatically.
