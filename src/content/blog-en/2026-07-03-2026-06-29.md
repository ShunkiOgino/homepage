By inserting a demo flag (`OGINO_DEMO=1`) at external API connection points, I reproduce authentic routing behavior with zero real data. This approach reduces both the cost of re-recording videos and the operational risk of exposing a live environment to zero, delivering only the tangible experience.

When trying to convey the value of a tool, my initial instinct was to either carefully record screen captures or simply make the live environment public. However, I realized that the former carries a high cost for revisions, and the latter entails risks regarding backend operational load.

For example, when releasing a self-made manga panel editor, I implemented it as a "hands-on demo" that users could actually touch, rather than using still images or videos. While the original tool depended on a server-side API, I extracted the client-side JS logic and replaced the API portions with stubs (static data), porting it into a self-contained HTML file that requires no backend. This made it possible to provide the core experience—arranging panels and editing text—directly via an iframe.

Furthermore, to maintain the "persuasiveness of authenticity," I use a strategy where I keep the actual backend but control only the appearance. By inserting a demo flag (`OGINO_DEMO=1`) at external API connection points, I implemented it so that deterministic dummy data is returned only for specific prompts. This safely reproduces the behavior where data in the correct format is rendered via actual routing.

Regarding demo video production, I eliminated the cost of manual recording by building a pipeline using Playwright to control transitions, clicks, and subtitle overlays via JSON-formatted scripts. For areas where selector specification was difficult, I resolved it with XY coordinate clicks to ensure reproducibility.

What is indispensable in this kind of design is the perspective of "how the recipient perceives it" rather than the "systematic correctness." To the user, the rendering looks as if it passed through actual routing, but in reality, it is a state of zero real data controlled by a single flag. Designing for visual and psychological conviction, rather than functional correctness, is essential for intuitive communication.

Where should the cost of conveying value be allocated? Instead of pursuing implementation complexity, I allocate resources to increasing the resolution of the experience. By optimizing that balance, the way a message is received changes dramatically.
